# Targeted boundary remediation design

This is a local research boundary, not production certification. Phase 2E's frozen holdout, six reserved live inputs/labels and original evidence remain immutable. Only new development fixtures and previously available development cases guide these changes.

## Routing contract

The router records four states: `verified_safe_fast_path`, `needs_semantic_review`, `deterministically_blocked`, and `unknown_or_uninspectable`. A block of unknown content is a policy quarantine, not proof of detecting an attack. Every routed result carries its reason, origin, capability, input-byte count and whether context was included. Model invocations, scoped cache hits, unavailability and budget rejections are counted separately.

A missing keyword does not establish trust. Untrusted prose, whether ordinary English, multilingual or unfamiliar, needs semantic review. Metadata cannot declare itself trusted or read-only. Capability resolution uses operator bindings, never caller labels or annotations. Metadata changes still face baseline consistency checks. Operator-pinned descriptor/content hashes skip semantic inference only for exact content at the approved stage, target and server; existing hard invariants still apply.

Fast paths cover non-instructional scalar outputs, validated client input to an operator-bound read-only capability, and bounded byte-exact echoes of that client input through the same read-only tool. Exact echo provenance is derived inside the HTTP/stdio adapter, never from a header or upstream annotation. Read-only retrieval outputs otherwise remain untrusted. Explicit descriptor hashes use canonical JSON object keys; the SDK can reorder schema properties on receipt. Existing externally configured definition hashes generated by the older insertion-order algorithm must be regenerated with the Phase 2F helper. Arrays and string contents remain significant.

Unicode NFKC and removal of format controls are used only for inspection. Delivered benign text remains byte-for-byte unchanged. Existing rules examine raw and normalized aggregate text, including compact item concatenation. No new attack-vocabulary rule was added. Multiple resource items and prompt messages receive a single bounded semantic review. Only delivered untrusted text enters the prior-context buffer; blocked content and verified client echoes do not poison subsequent session context.

Bounds: 16 KiB of inspection/model content (including prior context), 32 items per aggregate, 4,096 characters of rolling history per active server/session, 128 history scopes, 60-second history TTL, 256 operator content approvals, four active semantic operations, 128 queued operations, one-second queue deadline and 16 attempts per logical inspection request. Request counters are capped at 256 entries and expire. Multiple discovery/request contexts can exist within one transport exchange; this is not a global per-HTTP-provider-spending limit. The real adapter retains its request timeout; the manual runner independently reserves request/token/cost limits before paid dispatch.

When needed review is disabled, unavailable, malformed, contradictory or over budget, the result is unknown/review or quarantine. Gateway and engine defaults are now fail-closed. An explicit binary-policy opt-out is recorded as uninspectable rather than verified text. An explicitly configured `FAIL_CLOSED=false` can still deliver medium-risk review content with an audit warning; high-risk/uninspectable content is quarantined. This opt-out must not be presented as verified safety. Classifier confidence remains uncalibrated.

## Schema fidelity and validation

HTTP and stdio use the installed SDK 2.4.0 `fromJsonSchema` and its AJV validator. Accepted schemas are preserved structurally; validation neither coerces input types, inserts defaults nor strips extra fields. The current upstream schema is rechecked immediately before forwarding. Standalone stdio also refreshes the definition before invocation. Each distinct contract gets its own AJV instance to prevent `$id` collisions from selecting a different upstream's validator. The contract cache is bounded to 64 entries and keyed by server plus complete schema hash.

Supported: MCP object roots, nested properties, required fields, enums/const, arrays/items, unions, conditionals, numerical/string/collection bounds, supported formats and nonrecursive local JSON Pointer references, within declared draft-06/07, 2019-09 or 2020-12 dialects supported by the SDK. There are 64 KiB / 16-depth / 2,048-node schema limits; publication also depends on the router's separate metadata inspection bound. The root must explicitly declare `type: object`.

Deliberate local policy exclusions, **not SDK inability to preserve JSON**, include remote references, recursive/dynamic references, regex `pattern`/`patternProperties`, embedded dialect changes, undeclared custom validation keywords/formats, dialect-incompatible keywords and `x-mcp-header`. This avoids remote resolution, unbounded recursion, attacker-chosen regex work and unintended header projection. Unknown contracts are quarantined; there is no generic-record fallback. `x-*` annotations are retained but confer no validation semantics or privileges. Model results cannot authorize an unsupported schema.

## Subscription and cancellation scope

Persistent resource subscriptions are unavailable. Both HTTP and stdio advertise `subscribe: false` and `listChanged: false`; subscribe/unsubscribe handlers and upstream forwarding are removed. Tool/prompt list-change advertisements are also disabled. SDK-owned modern `subscriptions/listen` entry points have an explicit zero subscription limit in both serving transports, so they cannot create an unscoped stream behind the application handlers. Normal read/list/get operations remain supported. Raw requests, reconnects and bridge tests confirm no upstream subscription side effect. There is no hidden subscription registry, stale subscriber or cross-session notification relay to clean up.

Dispatched tool, resource and prompt SDK calls receive the downstream request's cancellation signal. This does not guarantee that an already-running upstream program stops, nor does it bound all discovery connection work. A complete persistent subscription implementation remains deferred rather than simulated.

## Local identity and future authenticated deployment

Default binding remains `127.0.0.1`; non-loopback configured hosts are rejected. HTTP admission additionally checks the socket peer and Host, and denies cross-origin browser requests. Client identity/session labels do not override these guards. Labels are correlation hints; a local Veylith session is a bearer capability. A stolen session plus matching forged label can still impersonate that local client. No remote endpoint is enabled here.

A future remote boundary needs TLS plus a token verifier **before** session creation/authorization: validate signature, issuer, audience, expiry and permitted scopes; derive the principal from the verified token; bind sessions to that principal and upstream; strip client-supplied identity/forwarding labels; permit only an explicitly trusted proxy/socket; add origin/CSRF controls if cookies are used. A reverse proxy forwarding unauthenticated traffic to loopback does not create authentication. Reuse the installed SDK's authentication interfaces rather than building an identity platform. No verifier, keys, cloud resource or remote listener is created in this phase.

## Retention, restart and rotation

Audit memory retains at most 2,048 records by default. Sequence numbers continue globally. The evicted prefix becomes an explicit `(nextSequenceNumber, previousEventHash)` checkpoint, so the retained tail verifies against its stated checkpoint. `verifyChain()` verifies the in-memory tail; it is not a full-history claim. Explicit record arrays start at genesis unless the caller supplies a checkpoint. Returned records are defensive copies.

Persistent archives are not truncated by retention. Startup streams and verifies every record using 64 KiB buffers before opening the writer; only the bounded tail remains resident. Lines are capped at 64 KiB. The default 64 MiB disk capacity fails closed before further writes. Previous lock/stale-writer/partial-write/fsync protections remain. Descriptor tracking is capped at 1,024 definitions/bindings and quarantines new definitions at capacity without forgetting existing mutation baselines. Semantic caches and context buffers are separately bounded.

Rotation is an explicit operator action: stop and flush the writer, verify and preserve the complete archive, record its byte digest/last event hash/record count, move it to an owner-protected archive, and start a separate genesis log. Preserve an authenticated external rotation index/checkpoint if cross-archive integrity matters. Never delete the archive or call the test-only `reset()` API as a production rotation mechanism. A stale lock requires reviewed recovery.

Local hashes/checkpoints cannot detect valid-prefix truncation after restart or full-chain regeneration by an attacker who can rewrite files and checkpoints. External anchoring/signing remains unresolved. Rotation is manual, filesystem trust is assumed, and a capacity failure can reduce availability. Neither retention nor a successful finite lifecycle test proves absence of memory leaks or power-loss durability.
