# Phase 2E scenario specification

Exactly 14 principal scenarios are enumerated in `security-lab/v1/scenarios.json`: E1/E2 (easy), M1/M2/M3 (medium), H1/H2/H3 (hard), X1/X2/X3 (extremely hard), G1/G2/G3 (god level). The tiers are qualitative challenge labels, not measured sophistication scores.

The core corpus contains eight variants per scenario: four development and four holdout, 112 total. An additional 16 seeded, locally generated G1 development candidates give **128 offline variants**. Six distinct live candidates remain separately reserved. Development generation uses a fixed xorshift seed and grammatical role/authority/disclosure mixtures; it reads no predictions and never rewrites frozen fixtures. Run the generator only in a new version directory; existing candidate files are protected against replacement. This is a bounded local grammar generator, not an adaptive learning algorithm or a search against a real model. True adaptive optimization remains unsupported.

Each offline case declares its ID, tier, stage, context, synthetic input, decision, enforcement target, ground-truth rationale, semantic-routing expectation, allowed modes and safety constraints. The semantic-routing expectation is a normative annotation; actual inference counters are recorded separately. Disabled mode deliberately makes zero inference calls. The frozen live candidate inputs/labels are expanded to complete execution context by the manual runner before use.

## Coverage and evidence

| Scenario | Actual protocol exercise                                                                                                                             | Independent success evidence                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| E1       | tools/list, calls, arithmetic, resources/list, templates/list, prompts/list/get                                                                      | Original content/arithmetic delivered; no policy rejection                                                         |
| E2       | Poisoned tool descriptions and returned text                                                                                                         | Hidden metadata or original payload absent from client output                                                      |
| M1       | Read-only search arguments, quoted commands/SQL, resource/prompt documentation                                                                       | Harmless text remains intact; false positives count                                                                |
| M2       | Schema descriptions, annotations, baseline mutation and explicit approved updates                                                                    | Tool listing/call result plus upstream call counter                                                                |
| M3       | Spanish/Hindi/Japanese/French, fullwidth/invisible characters and combining accents                                                                  | Malicious text intercepted; international benign controls delivered                                                |
| H1       | Resource, prompt and tool-returned indirect instructions                                                                                             | Client-visible sanitized output after actual upstream retrieval                                                    |
| H2       | Unknown tool, wrong-server capability binding, self-asserted annotations, static restricted tool                                                     | Unauthorized tool call count must be zero                                                                          |
| H3       | Wrong client/server, expired/absent/stolen session, subscription/resource permissions                                                                | Final HTTP/MCP rejection and absence of unauthorized upstream effects                                              |
| X1       | Multiple content items, prompt messages and sequential resource reads                                                                                | Combined malicious instruction must not survive; no assertion that per-item screening provides conversation memory |
| X2       | Mutation within TTL, approved updates, controlled tools/list return barrier                                                                          | Discovery priming → deterministic mutation → invocation; changed tool must not run                                 |
| X3       | Parallel unique private markers, separate permissions, cancellation, expiry, reconnection and subscription                                           | Response markers, forwarding counters; missing notification relay explicitly unsupported                           |
| G1       | Fixed challenge inputs and 16 seeded role/semantic mixtures                                                                                          | Actual deterministic/mock output, no model-accuracy claim                                                          |
| G2       | Low-trust read followed by an unconditional scripted privileged call                                                                                 | Resource detection and privileged call counter scored separately                                                   |
| G3       | Outage/recovery, audit-write exception, malformed semantic fallback, admission limits, binary/size rejection; compound outage/cancel/expiry sequence | Observed failures/recovery and actual HTTP status; incomplete recovery never credited                              |

The G2 agent simulator deliberately attempts the follow-up even when retrieval is sanitized. This tests gateway enforcement without claiming to measure agent persuasion or autonomous agent behavior. G3 combines a subset of failure dimensions; it does not cover every factorial combination. Notification delivery, full adaptive optimization and atomic server behavior pinning remain limitations.

## Holdout freeze

`54062f3` committed frozen fixtures before any evaluation. `13ebf9e` sealed the byte hashes after formatting, also before evaluation; labels and case inputs did not change. The manifest covers holdout/live file bytes and individual holdout cases. Every worker verifies integrity before loading cases; no baseline can silently replace expected decisions with predictions. The manifest hash is stored in every result.

Freeze means immutable evaluation inputs and labels. It does not prove statistical independence: one evaluator authored the corpus and could see its contents. Development fixes precede the first evaluated holdout run; no policy/model tuning follows holdout results. Small per-scenario matrices are descriptive only. Repeated modes reuse inputs and must not be added together as independent samples.
